# 项目课：模块规则

默认简体中文。这里写“项目课”这个模块的规则。整个仓库有哪些模块见仓库最外层的 [AGENTS.md](../AGENTS.md)，基础课件的规则见 [basics/AGENTS.md](../basics/AGENTS.md)。

## 现状

- 规划中，还没有课。仿照大学里分阶段做的项目：一个项目拆成几个阶段，每个阶段加一样东西，做完一段能跑、能测，再做下一段。
- 下面的“测试怎么写”还是提议，等老师确认后再定。

## 和基础课件的不同

- **代码在哪里跑：**项目代码在学生自己的电脑上写和运行，编辑器不限（Dev-C++、VS Code 都行）。只有课件页上的演示脚本用在线 IDE（cpp.sh）讲解。
- `basics/AGENTS.md` 里说学生不用 Dev-C++ 打开起始程序，那一条只管基础课件。项目课的代码在本地打开和运行。
- **谁写什么：**素材包（图片、音效这些材质）和显示画面的前端代码由老师提供，学生只写后端逻辑。
- **名字照抄：**引导文档里点名的重要函数、类和方法，学生必须用老师给的名字，一个字母也不能改，因为测试按这些名字调用。
- **每个阶段做对没有：**用老师提供的测试文件判断，学生运行测试，全部通过才算这个阶段做完。测试有两种：
  - 行为测试，比如“角色向上走一格”：调用学生写的函数，看位置变没变对。
  - 功能测试，比如 getter、setter 和 toString：在 C++ 里可以是 `toString()` 成员函数，也可以是 `operator<<`，用哪种由引导文档定。
- **怎么发给学生：**起始程序包由老师下载，用 U 盘发给学生。一个阶段一份：起始代码、前端、素材和测试。上课时学生不用上网下载任何东西。

## 测试怎么写（提议，待老师确认）

- 测试不能要求学生另外安装东西。两种做法：
  - 老师随包发一个很小的头文件，里面几个检查宏，比如 `CHECK(条件)`，失败时打印哪一项错了。
  - 用单个头文件的测试框架，比如 doctest（`doctest.h`，MIT 许可，许可文本随包一起发）。
- 两种都要能用普通的 g++ 编译，比如 Dev-C++ 自带的 g++，也要能在 VS Code 里编译运行。按 C++11 写。
- 测试文件只调用引导文档里点名的函数、类和方法。

## 先学哪些基础课

每个阶段写明要先学完哪几节基础课，用基础课件的文件夹名，比如：

- 用格子地图的阶段，要先学 `12-array`。
- 二维的格子地图，要先学 `14-2d-array`。
- 用结构体存角色、物品的阶段，要先学 `19-struct`；用函数拆开逻辑的，要先学 `17-function` 和 `18-scope`。

## 待定

- getter、setter 和 toString 要用 class。基础课 30 节讲了结构体（`19-struct`），没有讲 class。是在基础课里加一节 class，还是在项目课里讲，等老师定。
