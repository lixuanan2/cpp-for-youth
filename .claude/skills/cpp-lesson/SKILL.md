# 做一节 C++ 课

先读 [PROMPT.md](../../../basics/PROMPT.md)，那里是全部教学要求。这里只规定操作顺序。一次只做一节课。

课都在“基础课件”模块 `basics/` 里。下面的路径都从 `basics/` 算起，命令也都在 `basics/` 里运行（从仓库最外层先 `cd basics`）。模块规则见 [basics/AGENTS.md](../../../basics/AGENTS.md)。

## 1. 定设计

读 `course.json` 和上一节课的 `slides.html`，确认学生已经学过什么。再读 [模块内容摘要](../../../basics/docs/module-baseline.md) 里这一节，需要细节时读旧仓库的这一个 `习题/PART_xx`，实际进度看旧仓库的 `教学记录/`。给老师一份大纲：每页一句话，标出小测、预测、追踪、找错和项目放在哪里。

大纲超过约 30 页时，主动提出在哪里分上下集。

大纲定好后直接做，不用等老师审核，交付时把大纲和成品一起给老师。只改错字或单页时跳过这步。

## 2. 写程序和测试

新建 `lessons/<编号-英文名>/`，复制上一节的结构，在 `course.json` 给这节课补上 `id`、`tag`、`title` 和 `stage`。编号用新课号，比如 `04-branches`。分集时用 `05a-for-loop`、`05b-for-loop`，标题写“for循环（上集）”，每集占一行。

- `solutions/`：答案，每个都要有测试。只阅读的错误程序叫 `demo_*.cpp`。
- `starter/`：起始程序。小改写放例题程序，挑战和小项目只留框架（`#include`、`main`，要写函数的留一个空位置）。注释一律用中文；题目不写进这里：构建时按 `tasks.json` 的 `brief` 在开头加一段 `//` 注释，IDE 按钮、下载的文件和起始程序页都带上。基础例题没有 brief，起始程序里可以留一句中文注释说要做什么。
- `tests/contracts.json`：普通和边界数据。
- `tests/claims.json`：页面上说过的输出和报错，含小测的每个选项。报错写 `"error": {"gcc": "…", "clang": "…"}`：页面上的报错照 cpp.sh 真实显示的抄，`clang` 是页面那一行去掉 `main.cpp:` 的文字，框里每行一条 claim，做法见 `basics/AGENTS.md`。
- `tasks.json`：题目、角色（语法小演示、基础例题、学生小改写、独立迁移、创作项目）和页码。学生自己写的三种（小改写、独立迁移、创作项目）要有 `brief`，这是 IDE 里题目注释的唯一来源：`title` 和页面标题一样；`goal` 一到三句，照页面上的题目写（输入、范围、输出格式）；`hint` 一句提示，可省；小项目写 `more`：“先做到：…”“选你喜欢的：…”“还想更厉害：…”。样例用 `sample_input`、`sample_output`，页面上的例子不一样时可在 `brief` 里写 `input`、`output`；样例太长、缩成“……”看不出要点时写 `"sample": false`，把页面上的例子写进 `goal`；小项目没有样例。生成的注释最多 12 行。`check.py` 核对：标题、每个数字和引号里的词在那一页出现，样例是答案真的输出，注释里没有答案里的代码，不写“必做”“选做”这类标签，`dist` 里的起始程序是最新的。页面写“读入同上”时，`goal` 里不要写那一页没有的范围数字。下载的起始程序用 `site.json` 的 `"starter_encoding"` 存，C++ 课保持默认 `"utf-8"`：学生在大屏幕上用在线 IDE 写，IDE 按钮带的是文字，和编码无关。

## 3. 写页面

只在 `slides.html` 写 `<section class="slide">`。先从 `lessons/04-branches/slides.html` 找现成写法，组件都在那里：

| 需要 | 写法 |
| --- | --- |
| 编辑器 | `.editor` + `.tab` + `pre.code data-file` + `.ln` |
| 只显示关键几行 | `pre.code data-file="…" data-lines="7-13" style="counter-reset:ln 6"`，IDE 带完整程序 |
| 代码只是片段 | 页面只放几行、不是完整程序时，在 `tests/claims.json` 里给这页那条完整程序加 `"ide": true`，“本页代码进 IDE”就带它。读报错页也这样，学生在 IDE 里看到的是页面讲的同一个报错。停不下来的程序只写 `page`、`ide`、`code`，检查只编译不运行。`check.py` 会查每页进 IDE 的代码是不是完整、能运行的程序 |
| 语法高亮 | `.f` 函数，`.k` 关键字，`.s` 字符串，`.m` 数字 |
| 分步揭晓 | 页面加 `data-steps="3" data-at="3"`，元素加 `.step .s2`、`.only1`，行加 `.l1` |
| 逐步追踪 | 代码行加 `.l1 .l2 …`，第几步亮哪几行。`check.py` 用真实运行核对：把整个程序复制一份，在每个函数、每个循环和 else if 的判断处插记录，编译运行，每一步亮的行要在运行里连着出现，各步按顺序往后走；同一行可以连着讲两步（先看 && 左边，再看右边）。整个函数一起亮算“定义”，只核对函数头那一行；`} else {`、单独的大括号、`#include`、`using` 不算。停不下来的程序和越界的程序也照样跑，跑够了就截断。C++ 课的变量框（`<i>i</i><b>2</b>`）工具不核对，写之前自己按真实运行算一遍。程序要读输入时在 `pre.code` 加 `data-stdin="2 3&#10;"`，按页面上说的输入写；没写就用这页 claims 里同一程序的输入。页面只摘几行时要有 `data-file` 加 `data-lines`，或者 `data-full` 写**页面上这一版**的完整程序（错误写法的预测页尤其要注意，不要写成改对的程序），行号用 `counter-reset` 对上。只是指给学生看、不按运行顺序的一步写 `data-point="2"`，只核对这些行确实会运行。代码变化页里，旧版那几步亮的行：没变的行写在新版那一行上；改过的行（换字）新版那一行写上给页面看，旧版那一行也写上给检查看；新增的行在变化之前看不见，亮旧版里被删掉的那一行。`python3 tools/check.py --traces` 列出没法核对的追踪页和原因 |
| 选择小测 | `.quiz data-right="序号"`，选项加 `data-fb`，后面放 `.fb` |
| 点行找错 | `pre.code.pick data-bug data-yes data-no`，后面放 `.fb` |
| 黄色框 | 代码行里放 `input.slot data-var="名字" value="默认值"`，数字框加 `inputmode="numeric"`，不加 `maxlength`，填多了才看得到提示；文字框加 `data-kind="text"`，放在代码里写好的两个英文引号中间（`<span class="s">"</span><input …><span class="s">"</span>`），引号是页面代码的一部分，学生只填字。结果放 `.live-out` 里的 `b data-eval`，写好默认结果：`a / b` 这样的运算，或者只写一个名字。几次运算从左往右算，页面代码要用括号写成同样的顺序。数字是 0 到 9999 的整数；文字最多 12 个字，不能有引号（英文、中文都不行）和反斜杠。填了范围外的值（负数、小数、字母、超过 9999、引号、太长），页面不会偷偷改成别的数：框变红、结果变成“？”、编辑器下面出一句红色提示，按原因说一句孩子看得懂的话，框里打了引号就说“两边的引号已经写好了，框里只填字”；框清空时结果也是“？”，提示变成黄色的“框里空着”。IDE 按钮带的仍是学生填的原文，只有文字里的英文引号和反斜杠会转义，`??` 写成 `?\?`，免得变成三字符组。数字框不要放在 `{…}` 初始化里，学生填小数会编译不过。一页最多 2 个框，`data-eval` 按 `cout` 的顺序写。`check_browser` 会把所有组合拿真实 C++ 跑一遍，清空和填错时查提示。只改一个值、结果一眼能看到时才用；小改写和独立迁移的程序不要做成黄色框。例子见第 1、2、3 课 |
| 代码变化 | 讲“在上一版上加一行、改一处”时用。同一个 `.editor` 里先放旧版 `pre.code.was`，紧跟着放新版 `pre.code data-change="2"`，页面加 `data-steps`。翻到第 `data-change` 步时播放变化：没变的行不动，新增的行滑进来（绿条），删掉的行淡出，改过的行换字（黄条）；往回翻退回旧版；系统设了“减少动态效果”就直接切换。缩略图是旧版，PDF 是新版并标好颜色，IDE 按钮总是带新版。页面只摘几行时，两版摘同样范围的行，`data-lines` 和 `counter-reset` 对齐，行号才对得上。两版都要有测试：写 `data-file`；没有文件的写 `data-full`（完整程序），并在 `tests/claims.json` 给这页写上那一版的输出。旧版的 claim 不要带 `"ide": true`，不然 IDE 会带旧版。文件标签写中性的文件名，不写“这样写有问题”，因为第一步显示的旧版可能是对的。框里不能放黄色框。只改了缩进的行（外面套一层循环）会整行滑到新位置。合并两页时，旧版的几步在前，`data-change` 设成变化那一步，后面接新版的几步；只在某几步出现的字、结果、问号、标题用 `only1` 到 `only5`（可以写好几个，比如 `only1 only2 only3`），从某步起一直在的用 `step s2` 到 `s5`，高亮行用 `l1` 到 `l5`。没变的行和改过的行用的是新版那一行，旧版那几步的高亮要写在新版的行上。工具栏的“本页代码进 IDE”跟着这一步显示的按钮走，没显示的按钮点不到。编辑器要够宽：变化页的行放不下会被截掉，`check_browser` 会报。什么时候用、什么时候不用，见 `basics/PROMPT.md` 的“互动”。例子：第 6 课第 2 页（五行 cout 改成 for），第 4 课第 14 页、第 6 课第 9 页、第 9 课第 6 页、第 11 课第 8 页、第 12 课第 9 页、第 20 课第 11 页（预测页先放熟悉的程序，翻一步改一处再猜），第 5 课第 3 页、第 13 课第 9 页、第 21 课第 4 页、第 24 课第 2、4 页、第 25 课第 2 页（两页合成一页） |
| 算法演示 | 讲排序、查找、枚举这类“一步步重复同一件事”的算法时用，带播放键。页面上放算法程序的 `pre.code data-file="solutions/…"`，只显示几行就加 `data-lines` 和 `counter-reset`；旁边放 `<div class="algo" data-algo="…" data-stdin="4&#10;5 2 4 1&#10;" style="left:…;top:…;width:…;height:…">`，页面不写 `data-steps`。`build.py` 把整个程序复制一份，在 `main` 的每条语句前插一个记录，用和检查同一个编译器（`CXX`，否则 clang++、g++）编译运行，把每一步写进页面，动画和代码一定对得上；亮的行按原程序的行号对上页面的行，不在页面上的行不亮。程序要完整（有 `int main()`），只记 `main` 里的语句，每条语句单独一行，`} else if (…) {` 这一行不算一步，`printf` 不要和 `cout` 混用。三种：`sort` 加 `data-list="a"`，数组比数多（`int a[20]`）时加 `data-size="n"` 只画前 n 个，比较行写成一行 `if (a[j] > a[j + 1]) {`，交换用 `swap` 或三行 temp 都行（三行做完算一次交换），4 到 8 个数，画成柱子（黄色在比、红色刚换、绿色站好）；`search` 加 `data-lo data-hi data-mid data-target`，画成一条数轴，范围外变暗，数轴不超过 100 格；`try` 加 `data-var`，检查行写成一行 `if (甲 == 乙) {`，画成一排格子，试过的变暗、对上的变绿，可加 `data-speed="fast"`。旁边的代码跟着亮当前行，下面一句话由组件按步骤说明，再下面是“屏幕上”的输出。按钮：播放/暂停、上一步、下一步、重来、慢/中/快；键盘 P、`,` `.`、0、S，← → 照常翻页。减少动态效果时不自动播放；打印显示开始、中间两步和结束。一般放在右边，宽 600 以上（638 左右按钮不挤）、高 660 到 800，编辑器缩到 31 到 38 号字，标题上移到 `top:40px`，IDE 按钮放标题右边。`check.py` 用真实编译器再跑一遍原程序核对结果，`check_browser` 逐步核对柱子和亮行、按钮和按键、减少动画和打印。例子见第 21 课第 5、8 页（sort），第 30 课第 3 页（search），第 27 课第 9 页（try） |
| IDE 按钮 | `a.ide`，默认带本页程序；`data-code-file="starter/…"` 带起始程序 |
| 章节跳转 | 每章第一页的 `<section>` 加 `data-chapter="名字"` |
| 满版颜色 | `.dark` 听讲，`.band` 动手，`.clay` 挑战，`.olive` 复盘 |

页面用绝对定位，以 1920×1080 为准。放不下就拆页，不缩小字号。

## 4. 构建和检查

在 `basics/` 里运行：

```sh
python3 tools/build.py --pdf
python3 tools/check.py
node tools/check_browser.mjs --changed
```

`--pdf` 只重新打印页面变了的课，并更新 `pdf.json`；PDF 跟不上页面时 `check.py` 会报错。`--changed` 只查上次在本机通过后改过的课，改了模板或检查本身会自动查全部；`--status` 看哪些课要查。推送后 CI 会把全部课再查一遍，CI 和 Pages 都通过才算完成。然后看 `.preview/` 里的截图，每页和每个分步都要看。自动检查量不出丑不丑。

打开 `dist/<课>/index.html`，说明验证了什么、没验证什么。Windows 和投影只有老师现场能确认。更新 `basics/README.md` 的课程表；课数变了，同时改仓库最外层宣传 `README.md` 和 `home/index.html` 里的节数。提交并推送，看 CI 的 Windows 和 GCC 结果。老师的修改意见如果是通用的，写回 PROMPT.md，下节课就不会再犯。
